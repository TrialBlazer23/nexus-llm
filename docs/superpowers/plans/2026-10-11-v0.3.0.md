# Nexus-LLM v0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the 0.3.0 operator surface on top of the edge appliance already on `main`: cluster remote unload with an honest footer, opt-in Hexagon NPU prefill for BigMoeOnEdge v0.28.0, a fleet soak checker, and the release notes.

**Architecture:** Phase 1 (config, battery, full-weight fit, context/KV ladder, USB rank band, per-serial ADB, UUID merge, gateway routing, front-door load, doctor, product-name ban, USB probe RAM/backend) is commit `4a59f88` on `origin/main`. Do not re-implement it. Remaining work is three chains: unload/footer UI, local NPU prefill opt-in, and the soak log checker plus release docs. The phone decides NPU prefill from its own config. The hub never sends a device string for the peer to exec.

**Tech Stack:** Rust (`tokio`, `ratatui`, `reqwest`, `serde`), existing `bmoe-cli` subprocess, Bash setup scripts. No new crates.

## Global Constraints

- Hardware invariant from the release brief: lab devices are Nothing Phone 3 (16 GB), S23 Ultra (12 GB), and ~4 GB nodes (2009 Mac, Windows laptop, Galaxy A17, Moto Z2). Those names are acceptance context. They are not code constants, routing keys, or test-scan inputs.
- Penryn rustflags stay `-C target-feature=-avx,-avx2,-fma,-sse4.2`. A Hexagon build script must exit on `x86_64` before it configures or compiles.
- Android LMK ceiling stays 75% (`Model Size + KV Cache` against `MemAvailable`, and the same percent for MoE resident + cache + KV). Do not change `plan_fit_ladder`, `SystemProfile::from_advertised`, or `peer_offload_layers`.
- Sequential layer split only. No `--split-mode row`. No beacon v2. No networked MoE expert routing. No speculative decoding / MTP. Flash streaming stays single-token.
- No new crates. No internet download inside the fit ladder.
- Beacon wire format stays 64 bytes. Battery and power stay on `ControlPlaneState` plus mDNS `bat`/`pwr`.
- UUID is the node. ADB serial is the cable. `model:` from `adb devices -l` is a Tunnel-tab label only.
- Product-name ban test stays limited to the files it already scans. Do not edit the `galaxy-s23` fixture in `tests/test_discovery.rs`. The README `node_name` example `galaxy-s23-ultra` is pre-existing.
- `interactive_floor_tok_s` stays a TOML float stored as `interactive_floor_millis`. USB wins only when `score >= 0.85 * best_wifi`. Thermal cutoff stays index 75. Battery actions stay `decline` / `throttle` / `ignore`. Null battery stays eligible.
- `free_ram_mb` is raw MemAvailable. `allocatable_memory_mb` is the peer's own budget and is not stored in `free_ram_mb`.
- Control-plane unload already exists: `dispatch_unload_model` and `dispatch_unload_model_signed` post `ModelUnloadRequest` to `/nexus/control/v1/model/unload`. `model_path: None` calls `SupervisorManager::stop`.
- BigMoe `--prefill-device HTP0` is the only device token this release forwards. Any other token is ignored. Routed expert arena is the v0.28.0 default once that flag is set. Do not pass `--no-prefill-routed`.
- A host `bmoe-cli` built by `scripts/build-host.sh` has no Hexagon backend. Passing `--prefill-device` on that binary stays on the CPU. NPU prefill requires the opt-in Hexagon build plus `GGML_HEXAGON_HOSTBUF=1` and `ADSP_LIBRARY_PATH`.
- `BIGMOE_REF` is already `v0.28.0` in `scripts/versions.env`. That tag is the routed-arena release. Do not float the pin to `main`.
- Cleartext LAN stays the default. SECURITY.md must keep saying so. USB forwards are localhost on the hub and are not TLS.
- Cargo on this cloud VM is on PATH. Do not use the WSL wrapper. If `cargo test --locked` dies with signal 11 before any test prints, rerun once with `CARGO_INCREMENTAL=0`. Do not treat that startup crash as a product failure when the non-incremental run is clean.
- Pre-existing clippy `-D warnings` failures (`pantry_source_base`, `score_burst_candidate`, `fit_badge`) stay untouched.
- `src/gateway.rs`, `src/appliance.rs`, `src/discovery.rs`, and `src/ui/hub/mod.rs` are already past the 250-line guideline. Add the new pure functions in new files. Touch the large files only at the call site.

## Release brief (source, 2026-10-11)

**Nexus-LLM v0.3.0 Build Plan**
**Theme:** Edge Appliance — local front door + honest multi-device burst
**Target:** Turn the mesh into one prompt box. Ordinary chat stays on the machine you’re typing on (even a 4 GB node). Heavy work escalates to the best eligible Android peer over USB or Wi-Fi, with real fit checks, battery/thermal awareness, and multi-ADB support.
**Hardware invariant:** Nothing Phone 3 (16 GB), S23 Ultra (12 GB), 2009 Mac / Windows laptop / Galaxy A17 / Moto Z2 (all ~4 GB). Penryn-safe builds, Android 75% LMK ceiling, and no new crates stay locked.

### Goals

- Ship the locked edge-appliance design so the hub/gateway is the always-on entry point.
- Honest dense fit (full weights + KV + compute buffer) and MoE resident planner.
- Multi-device ADB (one localhost forward per serial) with UUID-based peer merge.
- Battery and thermal gating that actually affects placement.
- Close the remaining remote-unload gap.
- Bump BigMoeOnEdge and validate NPU prefill + larger MoEs on the 12–16 GB phones.
- Add a lightweight multi-node test harness that stresses the real fleet.

### Phase 1 — Edge Appliance Core (must ship)

Follow the existing task order in `docs/superpowers/plans/2026-10-10-edge-appliance.md`. Pure functions first, then wiring.

1. **Config & validation.** `ApplianceConfig` + `AdbConfig`. `interactive_floor_tok_s` round-trips as float → millis. Reject bad orchestrator paths and port collisions.
2. **Battery / power probe.** `probe_power()` + `ControlPlaneState` fields (`battery_percent`, `power_source`). mDNS TXT `bat`/`pwr`. Beacon wire format unchanged. Null battery stays eligible.
3. **Honest dense fit.** `load_estimate_mb = weights_mb + kv_mb + compute_buffer_mb`. Kill the 10% mmap discount for the verdict. MoE `streamable_moe()` path stays on `plan_moe_spawn`.
4. **Context / KV ladder.** `src/cluster/ladder.rs`. Walk requested context → 4096/2048/1024/512, F16 then Q8_0, then sibling quants. First fit wins. Interactive vs batch-only based on predicted tok/s.
5. **Burst ranking & USB band.** USB wins only inside the 15% band (`>= 0.85 * best_wifi`). Battery action (`decline`/`throttle`/`ignore`) and thermal index (75) applied before rank. Local orchestrator exempt from idle unload.
6. **Multi-ADB links.** One forward pair per authorized serial. Host ports from `18080` with stride 2, capped at `max_devices`. Persist probed ports in `~/.nexus/adb-links.json`. Peer merge on UUID; USB endpoints preferred while the forward answers.
7. **Route decision in the gateway.** Hub client stays on the local gateway when appliance + gateway are enabled. Tier-1 tags that the local model carries stay local. Escalation uses the ladder + rank. Burst models idle-unload after `burst_idle_secs`.
8. **UI / doctor surface.** Tunnel tab shows serials. Models badges show interactive/batch. Doctor reports USB serials and “no local model fits”. Status lines use the existing `role: "status"` path. Ban test prevents product-name routing inputs.

**Exit criteria:** Full `cargo test --locked` green. Manual acceptance on mixed USB + Wi-Fi with at least one 4 GB node and one 12–16 GB phone.

### Phase 2 — Completeness & Operator Surface

9. **Remote unload parity** (open item #11). Cluster view remote unload. Footer shows the true active model + host, not whichever peer you last chatted with. Control-plane unload already exists.
10. **Local orchestrator bootstrap.** On hub/`nexusd` start, load the smallest fitting GGUF tagged `orchestrator`/`router` (or the configured one) at low context. Skip tier-2 if none fits; tier-1 + escalation still work. Doctor warns when none fit.
11. **BigMoeOnEdge bump + NPU prefill.** Update `scripts/versions.env` and the build path to current BigMoeOnEdge (v0.28+). Expose `--prefill-device` / routed-expert arena when the peer advertises an NPU. Validate on S23 Ultra and Nothing Phone 3 with a model larger than RAM (Qwen3-Coder or DeepSeek V4 Flash class). Keep the lossless streaming guarantee.

### Phase 3 — Testing & Hardening

12. **Multi-node soak harness.** Scripted scenarios: simultaneous USB + Wi-Fi, cable yank mid-generation, battery floor trigger, thermal throttle, dense model on 4 GB node (must reject), MoE on 12–16 GB phone. Log route decisions, tokens/s, and failure recovery. Prefer the real fleet over synthetic profiles.
13. **Low-end device notes.** Document Moto Z2 (Android 8) as worker/client-only with prebuilt binaries if Termux bootstrap is painful. Confirm 4 GB x86 nodes stay responsive under the existing worker caps.
14. **Docs & changelog.** Update README with the appliance model (local front door, burst peers, USB vs Wi-Fi). Add v0.3.0 section to CHANGELOG. Keep SECURITY.md accurate (still cleartext LAN by default).

### Out of Scope for 0.3.0

- Beacon v2 or networked MoE expert routing.
- Speculative decoding / MTP (revisit after appliance is stable; flash-streaming path stays single-token).
- New crates or changes to Penryn rustflags / 75% LMK ceiling.
- Automatic model downloads inside the fit ladder.
- Full agentic tool-calling loops (can be a 0.3.x follow-up once the front door is reliable).

### Suggested Cadence

- Phase 1 first (the locked plan). Do not start Phase 2 until Phase 1 tests are green.
- Phase 2 and 3 can overlap once the gateway route decision is live.
- Target a tagged 0.3.0 once the soak harness passes on the actual device mix and the remote-unload UI is done.

```rust
pub struct Activity {
    pub local_model: String,
    pub chat_host: String,
    pub chat_model: String,
}

pub fn format_activity_line(activity: &Activity) -> String {
    let local = activity.local_model.trim();
    let host = activity.chat_host.trim();
    let chat = activity.chat_model.trim();
    let same = host.eq_ignore_ascii_case("local") && chat == local;
    if same {
        format!("local {local}")
    } else {
        format!("local {local} · {host} {chat}")
    }
}

pub enum UnloadChoice {
    Local,
    Peer { endpoint: String },
}

pub fn choose_unload(selected: Uuid, local: Uuid, endpoint: &str) -> UnloadChoice {
    if selected == local {
        UnloadChoice::Local
    } else {
        UnloadChoice::Peer {
            endpoint: endpoint.to_string(),
        }
    }
}
```

Empty `local_model` stays empty in the string. Callers pass `"None (Idle)"` when the supervisor is idle. `choose_unload` does not inspect the model name. The HTTP body uses `model_path: None`, which stops whatever that peer is running.

pub struct SessionView {
    pub local_model: String,

    pub chat_model: String,

pub fn on_local_load(view: &mut SessionView, model: &str) {

    view.chat_host = "Local".into();
    view.chat_model = model.to_string();
